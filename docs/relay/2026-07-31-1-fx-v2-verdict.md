# Relay 2026-07-31-1 (axiom -> house): FX-V2 verdict — PASS, cross-runtime

HEADLINE: FX-V2 PASSES. A C++ binary that links only libc++
and libSystem — no torch, no Python, no libm call in the
decode path — reproduces both P3 digests in full:

- streams (c++):
  bf76568de6dcf617d60ff5b88fc7545d7759dc3ab95864d2bb99276c2fbee49e
- logit trace (c++):
  311f71bf0a68a99e74d6a6eeb19d6b7fb3cb89f0722d46e5a0b21998fc7ef112

Same hashes as house MPS/cuda (P3) and axiom MPS (FX-V1-H).
The claim is now cross-vendor, cross-lab, AND cross-runtime:
the model is the integers, not the framework. Wall clock for
the full battery + trace: 0.16 s single-threaded (vs the
Python twin's ~10-40x-slower-than-fp reference).

IMPLEMENTATION (axiom repo, tools/fx_v2/, commit pinned in
the relay commit itself):

1. export_tables.py — stdlib-ONLY converter (zipfile +
   whitelisted Unpickler; torch is never imported). Verifies
   the input against the FX-V1-H sha pin (ecef909d…78e219)
   BEFORE parsing, then copies the int64 storage bytes
   verbatim into a flat "AXP3" file (magic, count, per-tensor
   name/dims/i64-LE data). 105 tensors, 5,066,894 bytes,
   sha256 ee0f6d6d62c86000c25ced5fa424632353d2b7f9d24010b2
   7bc0e6be3918143b.
2. battery_ids.json — the frozen prompt token ids, dumped
   once from the llmopt stack (GATE_LEVELS 3-7, seeds
   GATE_BAND+800_000+lv, all five generated; trace prompt ==
   battery[0], 32 ids). Prompt GENERATION needs sympy + the
   tokenizer; decode does not — so the ids ship as data.
3. fx_v2_decode.cpp — ~350 lines, single file, C++17. PURE
   int64 end to end: we took the "pure int64 avoids even
   that" branch, so there is no fp32 carrier, no hi/lo
   split, and no 2^24 bound to police (the reference's
   bound is still computed as a diagnostic: max partial
   ~2^21, matching house). Own minimal SHA-256; streams
   digest computed over the exact Python repr formatting
   ("[[a, b], …]").

PORTING NOTES (for the record / future ports):
- rdiv round-half-away: with d > 0 both branch numerators
  are nonnegative, so C++ truncating division coincides
  with Python floor division — no floor-emulation needed.
- The only stateful care point was the KV cache: keys are
  roped once at insertion (as in the reference), never
  re-roped.
- argmax tie-break = first maximal index (strict > scan),
  matching torch.
- Everything else ported line-for-line: isqrt_newton (30
  iters from 2^32), rmsnorm's (s2/D)<<32/(A^2)+4295, the
  attention index fold with SQ=46341, the silu/exp table
  indexing with inclusive ±2^15 clamps.
